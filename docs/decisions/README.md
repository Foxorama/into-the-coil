# Decisions

One decision per file, numbered and dated. This is where the *reasoning* lives, so that
`CLAUDE.md` can hold only the rule.

**Forward-only.** Every rule in `CLAUDE.md` names the decision behind it. The reverse does not
hold, and must not: demanding a rule per decision would force the constitution to grow to match
the archive. Measured on the predecessor, the two were roughly 1:3 — superseded passes, tuning
history and retired decisions are what an archive is *for*. Forward-only raises the price of
adding a rule, which is the intent.

**Written once.** A decision file is not maintained. If it is superseded, add a new file and mark
the old one superseded with a pointer — do not edit history into it. A file that gets revised is a
file whose reasoning can drift away from what was actually decided.

**Format.** Title, status line, the rule, then why — including what was rejected and the test that
rejected it. The rejected option is often the more transferable half: the next project inherits a
different codebase but the same reasoning.

Aim for a page. If a decision needs more than that, it is probably two decisions.
