### 1.2 Which devices v1 is for

[0153](../docs/decisions/0153-desktop-is-the-target.md): desktop is the target, and *"the phone is a
port that has not started."* But the game does run on glass
([0512](../docs/decisions/0512-the-touch-is-yours.md), [0566](../docs/decisions/0566-the-phone-pass.md)),
and the 0604 report that prompted a fix came from a phone. **The question is what the itch page and
the site claim**: desktop with keyboard or pad, plus *"also runs on phones"*, or phones supported. My
recommendation is the former, which needs no new work and keeps 0153 standing. itch's *mobile
friendly* flag follows from the answer.

### 1.3 Price

Free, pay what you want, or paid. The Far Carry is on itch with a donate link
(`far-carry/index.html` in the site repo). The soundtrack is already out, and the page links it either
way.

## Part 4 — before the tag, in the code

1. **The hangar resets on a version bump.** `src/save/hangar.ts:61` returns the empty document when
   `doc.v !== HANGAR_VERSION`. game.md's *Save and resume* says the keys are *"versioned from v1 with a
   migration chain."* Before v1 that costs only testers. After v1, the first bump wipes every player's
   ships, shards and looks. **Decide it before the tag**: build the chain's first link, or write down
   that a bump resets and why. The scores and settings keys are worth reading for the same question.
   *Checked:* the line, read on `main`. *Not checked:* `scores.ts` and `settings.ts`.
2. **The run save, if 1.1 builds it.** It needs a rollback note.
3. **game.md amended to the v1 answer** (1.1).
4. **`docs/state-of-play.md` rewritten.** Its *What is next* is forty headings of *owed a play*, and
   after Part 2 most of them are retired. That rewrite is what makes the file usable after v1.
5. **A release candidate first: tag `v0.9.0`**, which pushes to the itch channel while the page is
   still restricted, and **play it from inside the itch embed**. The itch player is the one surface
   nothing here has looked at: a fresh origin, an iframe, its own fullscreen button, and a viewport
   size the page sets.
6. **Bump to `1.0.0` and tag `v1.0.0`**, through `/ship`, the way #597 bumped 0.6.0.

## Part 5 — itch

None of this is in the repository. It is all in the itch dashboard, by the player's hand.

1. **The playable flag**: on Edit game → Uploads, tick *"This file will be played in the browser"* on
   the `html5` upload, and set *Kind of project* = **HTML**. Set once, ever: butler keeps it on every
   later push to the same channel (the comment at the top of `release.yml`). Possibly done already;
   see *Not checked* above.
2. **Embed options**: viewport size (the game is landscape), *fullscreen button* on, *mobile friendly*
   per 1.2, and *automatically start on page load* off, so the press that starts the sound is the
   player's.
3. **Never replace the upload by hand.** A new upload is a new origin, and every player's save stays
   behind in the old one (scaffold plan, setting 28). Only the tag pushes.
4. **The page**: title, a short description, a body in the voice of the Far Carry's (`ITCH.md` in the
   site repo is that page's source; the Coil wants its own beside it), genre *Shooter*, tags, and the
   soundtrack's links.
5. **Art**: cover image 630×500, and screenshots, shot from the real game with `scripts/shot.mjs`, not
   the browser pane. A trailer could be cut from the album's track videos.
6. **Saves are per place**: one line on the page saying that a save on itch and a save at
   `intothecoil.vulpecula.games` cannot see each other. The Far Carry guide already says this for its
   own game.
7. **Pricing** per 1.3.
8. **A launch devlog** on the itch page, since the site's `DEPLOY.md` makes itch the home of devlogs.
9. **Visibility → Public**, on release day, after `v1.0.0`'s itch job is green.
